**事故 G：登录首次返回 500**
- 现象：第一次调 /api/auth/login 返回 code=500，堆栈 `RedisCommandTimeoutException: Connection initialization timed out after 2 second(s)`
- 原因：`spring.data.redis.timeout` 只有 2 秒，WSL 端口转发首次 TCP 握手超过 2 秒；第二次请求连接已建好就正常
- 修复：timeout 与 connect-timeout 改为 5000ms，另加 shutdown-timeout 与连接池保活
- 教训：**首次慢、重试就好**的故障最容易被误判成"偶发"，其实是超时配置贴着临界值

**事故 H：404 只改 body 不改 HTTP 状态码**
- 现象：越权访问返回 HTTP 200 + body 里 code=404，测试与前端都按状态码判断，误判成成功
- 根因：全局异常处理器统一返回 `Result`，没给 NOT_FOUND 加 `@ResponseStatus`
- 修复：新增 `NotFoundException` + 独立 handler 返回 HTTP 404
- 意义：接口成功率报表若按 HTTP 状态统计，body 里写 404 会让成功率永远 100%

**事故 I：测试脚本把中文当 GBK 解析，连带响应体解码错误**
- 现象：中文断言全失败，部分 `Where-Object` 过滤结果为空
- 根因两条：
  1. `.ps1` 里写中文（无 BOM UTF-8）被 PowerShell 5.1 按 GBK 解码，引号被破坏
  2. `Invoke-WebRequest` 的 `.Content` 在响应头无 charset 时按 ISO-8859-1 解码，中文字段全成乱码
- 修复：脚本纯 ASCII（中文用 `[char]0xXXXX` 拼）；响应体改用 `RawContentStream` + UTF-8 显式解码
- 教训：**同一个中文编码问题，服务端、脚本、终端三层各踩一次**
